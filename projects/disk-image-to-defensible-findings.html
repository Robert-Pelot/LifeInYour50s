From Disk Image to Defensible Findings

Academic forensic exercise  •  Sanitized portfolio case study
IMAGE → VERIFY → DISCOVER → DOCUMENT → CORRELATE → REPORT

The useful result was not simply finding files. It was building a traceable path from the forensic image to a finding another examiner could evaluate.

At first glance, digital forensics can look like a search problem: find the interesting file and explain what it means.

This project changed that view for me. I worked through a 39-page forensic evidence packet built from an E01 image of removable media. The exercise ultimately documented 55 numbered evidence items across seven investigative sections, with artifacts drawn from documents, email, attachments, browser data, encrypted material, archives, and other locations in the image.

The more important lesson was that finding an artifact is only the beginning. A defensible result needs integrity, source context, metadata, correlation, and a report that clearly separates what the evidence shows from what the examiner thinks it might mean.

Public-safe version: names, passwords, exact source paths, cryptographic hash values, and case-specific allegations are intentionally omitted. The investigative method and technical lessons are preserved.

Case at a Glance

Source examined: forensic image of a 122 MB USB device

Acquisition: E01 image created with FTK Imager

Integrity: MD5 and SHA-1 values recorded and successfully verified

Scope: 39-page evidence packet, 55 numbered evidence items, seven investigative sections

Preserve Before You Interpret

The examination began with a forensic image rather than live media. The source information, image format, acquisition details, and cryptographic verification were recorded before analysis.

The packet also documented successful verification more than once. That reinforced a basic rule that became much more concrete during the exercise: before asking what the evidence means, first establish that you are still examining the same evidence.

If the source cannot be trusted, every conclusion built on top of it becomes harder to defend.

The Evidence Landscape Was Broader Than One Folder

The evidence did not live in one convenient directory or one file type. Relevant material appeared across ordinary user documents, images, spreadsheets, email messages, attachments, Outlook data, text files, HTML and browser-cache artifacts, archive contents, encrypted files, and presentation material.

Files & documents
Images, Word documents, text files, spreadsheets, and presentation material

Messaging
Email messages, attachments, and mail-store artifacts

Browser artifacts
Temporary Internet files and cached HTML content

Protected content
Encrypted files and archived material

Metadata
Hashes, source paths, and created / modified / accessed timestamps

That breadth changed the way I approached the image. A forensic question rarely stays inside one application. The useful evidence can be scattered across user folders, email stores, cache locations, temporary files, and protected containers.

An Artifact Needs More Than a File Name

Each evidence item followed a consistent structure. The packet recorded the file name, source path, encryption status, cryptographic hashes, timestamps, and a short description of why the artifact mattered.

That structure is what turns an interesting file into something reproducible. Another examiner should be able to understand where an artifact came from, distinguish it from similar material, and see which metadata supported the observation.

Correlation Made Individual Artifacts More Useful

One of the clearest lessons came from seeing related evidence appear in different places. In one sanitized example, an email artifact was associated with an attached protected document, while a related encrypted spreadsheet existed elsewhere in the image.

Each artifact could be documented independently. Together, they provided stronger context than any one item could provide alone.

This is the difference between cataloging and analysis. Cataloging says what is present. Correlation asks which artifacts appear to belong to the same activity, topic, or sequence—and then records that relationship without overstating what it proves.

Metadata Is Evidence, but It Has Limits

Created, modified, and accessed timestamps were recorded throughout the packet. When those values are present and plausible, they can help establish sequence and chronology.

But several entries contained unusable zero-value timestamps rather than meaningful dates. That became a good reminder that metadata should be examined, not worshiped. Missing or invalid timestamps are not permission to invent a timeline. The limitation itself belongs in the analysis.

What the evidence can support

  • A file existed in a documented location.
  • A recorded hash identifies the examined artifact.
  • Usable metadata can support chronology.
  • Related artifacts can strengthen context.

What it cannot prove by itself

  • Who necessarily created the file.
  • Why it was created or stored.
  • Whether someone acted on its contents.
  • Facts that simply are not present in the evidence.

Encryption Changes the Workflow

Several artifacts in the packet were marked as encrypted, and recovered access information was documented as part of the examination.

That changes the workflow because the presence of a protected file is not the same thing as access to its contents. The protection state has to be recorded, the access method has to remain tied to the evidence record, and the examiner still has to document the artifact after it becomes accessible.

The public version intentionally leaves the passwords themselves out. The important point is the process, not the secret.

Observation Before Interpretation

The dataset contained material that could easily tempt an examiner into dramatic conclusions. The more professional approach is to separate observation from interpretation.

I can state that an artifact was present, where it was located, what hash identified it, what metadata was recorded, and which other artifacts appeared related. The conclusion should go only as far as those facts allow.

OBSERVATION → CORROBORATION → SUPPORTABLE FINDING

Not every association proves authorship, intent, or action. A forensic report has to preserve that boundary.

Reporting Is Part of the Examination

The final packet was organized into numbered evidence items so a reader could move from a finding to the supporting artifact, then back to the source location, hashes, timestamps, encryption state, and description.

That is much stronger than a folder full of screenshots. Screenshots can illustrate what an examiner saw; an evidence record explains where it came from and why the reader should trust that it is the same artifact being discussed.

Techniques and Tools Demonstrated

The exercise combined evidence integrity, file-system examination, metadata review, email and attachment analysis, encrypted-artifact handling, cross-artifact correlation, and structured reporting.

What I Took Away

This project made forensic work feel less like searching and more like controlled documentation.

The question I kept coming back to was simple: Can another person follow the path from my conclusion back to the artifact that supports it?

That is the part I would carry into a real investigation: preserve the source, verify integrity, record what was found, correlate related evidence, acknowledge missing or unreliable metadata, and make the final report strong enough to stand without relying on the examiner's memory.

Digital forensics is not about telling the most dramatic story. It is about building the most supportable one.
